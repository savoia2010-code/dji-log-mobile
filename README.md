# dji-log 飛行日誌（iPhone単独版・実験）

DJIの飛行記録から国交省様式1の飛行日誌を作るWebアプリ。**iPhoneだけで完結**します。
Mac版（`../dji-log`）とは別の実験プロジェクトです。

## 特徴

- **サーバー不要**：解析・保存・Excel出力をすべてブラウザ内で行う
- **DJI APIキー不要**：暗号化されたログでも、飛行日誌に必要な項目は平文のまま読める
- **ホーム画面に追加**すればアプリのように使える（オフライン可）
- 飛行記録は端末外に出ない（住所表示のときだけ国土地理院に座標を問い合わせる）
- **飛行日誌を携行・提示できる**：Mac版の飛行記録・日常点検記録・点検整備記録を受け取り、圏外でも見せられる
- **具備資料も携行できる**：Mac版で作った機体の書類（製造者・運用限界・追加基準への適合性）、許可書・承認書のPDF、保険の情報を一緒に受け取って提示できる
- **日常点検記録（様式2）を現場で記録**し、あとからMac版へ送れる（iCloud Drive経由）

## 使い方

1. iPhoneのSafariでこのアプリを開く
2. 共有ボタン →「ホーム画面に追加」（アプリとして使えるようになる）
3. 「飛行記録を読み込む」→「ファイル」App →「このiPhone内」→ **DJI Fly** → **FlightRecords**
   → .txt を選択（まとめて選べる）
4. 設定で操縦者氏名と機体の登録記号（JU〜）を入力
5. 記録をタップして目的・特定飛行などを補記
6. 「様式1 Excelを書き出す」→ 共有シートから「ファイル」Appに保存

### 飛行日誌を携行する（Mac版から受け取る）

取扱要領 4.(7) により、飛行させるときは飛行日誌（飛行記録・日常点検記録・点検整備記録）を
常に携行し、求められたら提示できるようにしておく必要がある（点検整備記録は全件。5.(3)b)）。
記録の大元はMac版にあるので、それをiPhoneに持ち歩く。

1. Mac版を起動しておくと、iCloud Drive の「dji-log 飛行日誌」→「携行用」に
   `飛行日誌_携行用.json` が自動で書き出される（記録が変わるたびに更新）
2. iPhone版の「携行」タブ →「Macから受け取る」→ そのファイルを選ぶ
3. 機体ごとに、日常点検記録・点検整備記録・飛行記録を表示できる（端末内に保存されるので圏外でも可）。
   このiPhoneで記録してまだMacに反映されていない点検も「iPhoneのみ」として一緒に表示する

**その日の飛行は、飛行が終わるたびに「記録」タブで読み込むこと。** 飛行記録は「飛行させた都度」
記載するもの（5.(1)a)）で、携行用ファイルに入るのはMac版に取り込み済みの飛行だけのため。
読み込んだ飛行は携行タブに「iPhoneのみ」として並び、総飛行時間はMac版の最後の値から
（1飛行ごとに分へ切り捨てて）数える暫定値になる。Mac版に取り込まれると、DJIの記録ファイル名で
照合して二重には並ばない。携行タブの先頭の「今日の記録」で、その日の点検・飛行の記録の有無が分かる。

**具備資料**は、Mac版の「具備資料」で作ったものが携行用ファイルに入って届く。携行タブの
「具備資料（機体）」と「許可書・承認書と保険」に出る。許可書・承認書は審査要領 4-(18) により
原本又は写しを携行するもので、PDFは「許可書のPDFを開く」か「共有・保存」で見られる。
「今日の記録」には許可書の期限も出る。

**ホーム画面に追加して使うこと。** Safariで開いたままだと、しばらく使わないうちに
保存した記録が消されることがある。アプリは保存の継続（`navigator.storage.persist()`）を
求め、ホーム画面から開いていない場合は案内を出す。

### 日常点検を記録してMac版へ送る

1. 「点検」タブ →「点検を記録する」。飛行前に行った点検の結果を入れる
   （「現在地の住所を入れる」で実施場所を自動入力できる。圏外でも記録自体はできる）
2. 「Macへ送る」→ 共有シートの「"ファイル"に保存」→ **iCloud Drive の「dji-log 飛行日誌」**
   フォルダに保存（このフォルダはMac版が自動で作る）
3. Mac版が30秒ごとにフォルダを見に行き、点検記録画面に取り込む

記録ごとに識別子と更新日時を持たせているので、同じ記録を何度送ってもMac側で重複しない
（新しい方が採用される）。ファイルの形式は Mac版の `app/icloud.py` と合わせてある。

## 動かし方（開発時）

```bash
python3 -m http.server 8310 --directory dji-log-mobile
```

iPhoneから使うには、同じWi-Fi上のMacのIPアドレス（例 `http://192.168.1.5:8310`）を開く。
ホーム画面に追加して常用する場合は、HTTPSで配信できる場所（GitHub Pages等）に置くのが確実。

## なぜDJI APIキーが要らないのか

v13以降のDJIログは暗号化されており、飛行経路（フレーム）の復号にはDJIサーバーから
取得する鍵が必要です。ただし**ログ先頭のDetailsブロックは平文**で、そこに

- 飛行開始時刻・飛行時間
- 累積移動距離・最高高度
- 離陸地点の緯度経度
- 機体名・シリアル番号

が入っています。飛行日誌に必要な項目はこれで揃うため、復号せずに済ませています。
Mac版のフレーム解析と値が一致することを実ログで確認済みです。

（ブラウザからはDJIのAPIがCORSで叩けないため、仮に復号したくてもできません。
飛行経路の詳細な分析が必要な場合はMac版を使ってください。）

## 実機に触らずに検証する

iPhoneを出す前に、Safariと同じWebKitエンジンで自動検証できる。**Xcodeは不要**。

```bash
npm install
npx playwright install webkit
npm run serve &
node tools/verify-webkit.mjs "path/to/DJIFlightRecord_....txt"
```

iPhone 15の画面サイズで、WASM解析・IndexedDB保存・Excel生成・レイアウト崩れ
（横スクロール、ラベルのはみ出し）を確認し、`webkit-shot.png` を残す。

点検の記録・携行用ファイルの受け取り・その日の飛行の扱いは、`npm test` でまとめて確かめられる
（一時的にサーバーを立て、`tests/fixtures/` の架空のデータだけを使う）。

個別に動かす場合は次のとおり。

```bash
node tools/verify-inspections.mjs /path/to/out.json
node tools/verify-carry.mjs /path/to/飛行日誌_携行用.json [画面写真.png]
node tools/verify-today.mjs /path/to/飛行日誌_携行用.json <その日の記録.txt> <日時ISO> [期待する総飛行時間]
```

実機でしか確かめられないのは次の2つだけ:

- 「ファイル」App から DJI Fly → FlightRecords を選ぶ操作
- ホーム画面に追加したときの動作（Service Workerは**HTTPSかlocalhostが必要**。
  `http://192.168.x.x:8310` では登録されない）

## Mac版との違い

| | Mac版 | iPhone単独版 |
|---|---|---|
| 記録の取り込み | USB接続で自動 | 「ファイル」Appから手動選択 |
| DJI APIキー | 必要 | 不要 |
| 住所 | 番地（街区・地番）まで | 番地（地番）まで |
| 飛行経路の解析 | あり（最大変位など） | なし |
| 飛行日誌の作成 | ○ | ○ |
| 日常点検記録 | ○ | ○（Mac版へ送れる） |
| 飛行日誌の携行・提示 | — | ○（Mac版から受け取る） |
| 点検整備記録 | ○ | なし |

## 公開してよいのか（セキュリティ方針）

このリポジトリは**一般公開して問題ない**設計にしてある。

- **飛行記録はリポジトリに入らない**。読み込んだログも解析結果も、利用者の
  ブラウザ内（IndexedDB）にのみ保存される。`_test/` は `.gitignore` 済み。
- **APIキーを持たない**。暗号化ログの復号を行わないため、DJIの認証情報が不要。
- **外部に送るのは座標だけ**。住所表示のため国土地理院に緯度経度を問い合わせる。
  それ以外の通信は行わない（CSPの `connect-src` で機械的に制限している）。
  点検記録をMac版へ送るときも、アプリは通信しない。利用者が共有シートで
  保存先（iCloud Drive）を選んで、ファイルとして渡す。
- **CSP** を設定し、外部スクリプトの読み込みと想定外の送信先を禁じている。
  読み込むログは信用できない入力として扱い、画面表示は全て `textContent`
  経由（`innerHTML` にはユーザー入力を渡さない）。
- **同梱している第三者コード**は公式配布物とSHA-256が一致することを確認済み。
  - `vendor/dji_log_parser_js.mjs` … dji-log-parser 0.5.7（MIT）
  - `vendor/xlsx.mini.min.js` … SheetJS 0.20.3（Apache-2.0）
    npm版の 0.18.5 には CVE-2023-30533 / CVE-2024-22363 があるため、
    修正済みの公式CDN版を使っている（本アプリは書き出し専用で当該CVEの
    影響を受けないが、念のため）。

なお GitHub Pages ではHTTPヘッダーを設定できないため、`frame-ancestors` に
よる埋め込み防止は付けられない。サーバーへ送信する操作を持たず、記録はすべて
端末内で完結するアプリなので実害は小さい。

## 構成

- `js/parser.js` — WASM版 dji-log-parser でログを解析
- `js/db.js` — IndexedDB への保存と飛行判定
- `js/geocode.js` — 住所の組み立て（国土地理院の逆ジオコーダ）
- `js/blocks.js` — 市街地の番地（国土交通省 街区レベル位置参照情報のタイル）
- `js/parcels.js` — 郊外の地番（法務省 登記所備付地図データ）
- `tools/build-isj-tiles.mjs` — 街区データを取得してタイルに分割する
- `js/export.js` — 様式1のExcel生成（SheetJS）
- `js/inspections.js` — 日常点検記録の入力と、Mac版へ送るファイルの書き出し
- `js/carry.js` — Mac版から受け取った飛行日誌の保存と提示、記録を消されないための対策
- `vendor/` — dji-log-parser (MIT) / SheetJS (Apache-2.0)
- `data/muni.json` — 市区町村コード表（国土地理院）
- `data/isj/<県コード>/` — 街区レベル位置参照情報のタイル（国土交通省）

## 住所が番地まで出る仕組み

町丁目は国土地理院の逆ジオコーダで求め、その先の番地は2つのデータを順に試す。
片方だけでは穴が空くため両方必要:

| | 収録範囲 | 例 |
|---|---|---|
| 街区レベル位置参照情報 | 住居表示のある市街地 | 福山市元町13番付近 |
| 登記所備付地図データ | 郊外の地番 | 加茂町字北山1197-1番付近 |

街区データはブラウザから国土交通省へ直接取得できない（CORS）ため、
`tools/build-isj-tiles.mjs` で5.5km四方のタイルに分割して同梱している。
1回の検索で読むのは1タイル（中央値28KB）だけ。

**現在収録しているのは広島県（34）と岡山県（33）。**他県で飛ばす場合は下記で追加する。

```bash
node tools/build-isj-tiles.mjs 31   # 鳥取県を追加
```

未収録の県では、郊外は地番が出るが市街地は町丁目までの表示になる。
